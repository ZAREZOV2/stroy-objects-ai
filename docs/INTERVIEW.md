# Шпаргалка к собеседованию (для junior)

Кратко: **что делает каждая часть проекта** и **как ответить на типичные вопросы**. Код лежит в `app/`.

---

## 1. Общая схема

Один сервис **FastAPI** (`app/main.py`):

- HTML-страницы — `app/web/routes.py` + шаблоны `app/templates/`.
- JSON API — `app/api/objects.py`, `app/api/rag.py`.
- Бизнес-логика — `app/services/`.
- Таблицы — `app/models/`, миграции — `alembic/`.

База **PostgreSQL**; для RAG включено расширение **pgvector** (колонка `embedding` размерности 1024 под модель **bge-m3**).

---

## 2. Модуль «Учёт объектов»

### Таблицы

- `construction_objects` — карточка объекта (тип, МО, статус, даты, бюджет).
- `object_history` — кто что менял: при обновлении в `app/services/objects.py` сравниваются поля и пишется строка истории.

### Просрочка

Метод `ConstructionObject.is_overdue()` — если статус не «сдан» и `planned_end` в прошлом → просрочен. Фильтр `overdue` в API и на странице списка.

### Excel

`app/services/excel.py` — pandas читает CSV/XLSX, создаёт объекты через тот же `create_object`, что и API. Экспорт — DataFrame → openpyxl.

### Вопросы на собеседовании

**Почему FastAPI, а не Flask?**  
Нужен async под БД, автоматическая OpenAPI-документация, Pydantic для валидации входных данных.

**Зачем Alembic?**  
Чтобы схема БД хранилась в git и одинаково накатывалась на dev и сервер (`alembic upgrade head`).

**Как работает история изменений?**  
Перед `setattr` сохраняем старое и новое значение в `object_history` — простой audit trail без отдельной системы.

## 3. Модуль «ИИ-помощник» (RAG)

### Загрузка документа

1. Файл → текст (`pypdf` / `python-docx` / UTF-8) в `ingest.py`.
2. `split_text()` — нарезка на абзацы (~650 символов) в `chunking.py`.
3. Для каждого чанка — запрос эмбеддинга в Ollama (`bge-m3`) → сохранение в `document_chunks`.

### Ответ на вопрос

1. Если вопрос про просроченные объекты — ответ из SQL (`mode=objects`), без LLM.
2. Иначе поиск фрагментов: сначала **векторный** (pgvector `<=>`), если Ollama недоступен — **BM25-подобный** скоринг в Python (`search.py`).
3. Если Ollama есть — `generate` с **Spark-X2.5-1.7B** (или **4B** из `.env`), контекст ограничен (`OLLAMA_NUM_CTX=1536` по умолчанию).

### Почему bge-m3 и Spark?

- **bge-m3** — мультиязычные эмбеддинги, **русский**.
- **Spark-X2.5-1.7B** — чат по умолчанию для VDS 4 CPU / ~7 ГБ RAM; **4B** — опционально; Ollama ≥ 0.34.1.

### Fallback

Если GPU/моделей нет — приложение не падает: показываем сообщение на `/assistant` и отдаём найденные фрагменты текстом.

### Вопросы

**Что такое RAG?**  
Retrieval-Augmented Generation: сначала ищем релевантные куски документов, потом (опционально) LLM формулирует ответ по ним — меньше «выдумок».

**Зачем pgvector?**  
Храним векторы рядом с объектами в одной БД, ищем ближайшие соседи одним SQL-запросом.

**Как снизить потребление RAM на VDS?**  
Меньше `OLLAMA_NUM_CTX`, один loaded model в Ollama, меньше чанков в промпте; см. `docs/DEPLOY.md`.

## 4. Docker

- `db` — образ `pgvector/pgvector:pg16`.
- `app` — при старте: миграции + `scripts/seed.py` + uvicorn.
- `ollama` — профиль `ollama`, образ **0.34.1**, переменные `OLLAMA_MAX_LOADED_MODELS=1`.

---

## 5. Тесты

- `tests/test_api_objects.py` — CRUD и фильтры через HTTPX + ASGI.
- `tests/test_rag_chunking.py` — нарезка и keyword search.
- `tests/test_ollama_utils.py` — обрезка контекста.

Фикстура `conftest.py` поднимает таблицы в PostgreSQL и откатывает транзакцию после теста.

---

## 6. Что сказать про безопасность (если спросят)

Сейчас демо **без авторизации**. В production: reverse proxy, HTTPS, секреты в `.env`, отдельные пользователи БД, лимит размера upload, не открывать Ollama/Postgres наружу.
